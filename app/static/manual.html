CargoPlus 用户手册与集成指引

用于将邮件正文、附件和物流单证转换为约定的结构化业务数据。本手册仅说明客户接入所需的外部接口和使用规则。

首次接入建议：直接查看第 10 章，从上传文件到获取结果完整走一遍。

1. 接入准备与快速验证

当前客户测试环境 Base URL：https://115.29.213.72:30010。调用地址必须使用该 IP，改用其他主机名会造成证书名称不匹配。

客户需要准备 API Key；只有使用 Webhook 时才需要 Webhook Secret。两项凭据用途不同，不能互换。

首次安装根证书

本环境使用 CargoPlus 内部 CA 证书。首次调用前，先通过安全渠道取得 caddy-root.crt，再通过另一个渠道取得项目方提供的 SHA-256 校验信息。根证书用于建立连接信任，可以分发给调用端；API Key 用于业务鉴权，必须严格保密。

# Windows 当前用户：先核对文件 SHA-256，再导入受信任的根证书颁发机构
certutil -hashfile .\caddy-root.crt SHA256
certutil -user -addstore Root .\caddy-root.crt

# Ubuntu / Debian
sudo cp ./caddy-root.crt /usr/local/share/ca-certificates/cargoplus-caddy-root.crt
sudo update-ca-certificates

# Java：导入客户应用自己的 TrustStore
keytool -importcert -alias cargoplus-ip-ca -file caddy-root.crt -keystore cargoplus-truststore.p12 -storetype PKCS12

# Python requests 或 Node.js 未读取系统证书库时（PowerShell）
$env:REQUESTS_CA_BUNDLE = "C:\证书目录\caddy-root.crt"
$env:NODE_EXTRA_CA_CERTS = "C:\证书目录\caddy-root.crt"

Linux 容器应把根证书复制到镜像的系统 CA 目录并执行对应发行版的证书更新命令；Java 应使用独立 TrustStore。证书导入后，请关闭并重新打开浏览器、PowerShell 或调用程序。

健康检查

curl "https://115.29.213.72:30010/health/ready"

准备就绪时返回 HTTP 200，且 status=ready、database=ok、queue=ok。

禁止绕过校验：不得使用 curl -k、Python verify=False 或关闭 TLS 校验。未完成证书核验和信任安装前，不得上传真实业务文件。

2. API 鉴权

除健康检查外，客户接口需在请求头中携带 API Key，以下两种方式任选其一：

Authorization: Bearer <YOUR_API_KEY>
X-API-Key: <YOUR_API_KEY>

鉴权成功后可查询任务列表；缺少或无效 Key 应返回 HTTP 401。

3. 异步文件上传（推荐）

POST/api/v1/extract/async/upload

客户直接上传原始文件，系统负责文件解析、必要的图像识别和业务字段抽取。接口立即返回 task_id，客户随后轮询任务或等待 Webhook。

表单字段必填说明
files是可重复传入，表示同一业务任务的多个文件
mail_subject否邮件主题，最长 255 字符
recognition_mode否standard（默认）或 high_accuracy
callback_url否任务完成回调地址；正式环境必须是公网 HTTPS

支持格式与限制

.eml、.pdf、.xlsx、.xls、.docx、.doc、.jpg、.jpeg、.png、.bmp、.webp、.tiff、.txt、.csv、.json、.md。

限制当前值说明
单次文件数最多 10 个同一业务的邮件和附件可作为一个任务
普通单文件最大 50MB超出时拆分或压缩
旧版 .doc最大 20MB建议优先转为 .docx
单次文件总量最大 100MB超出时拆分为多个任务
PDF 页数最多处理 20 页高精度模式超限会失败；标准模式仅处理前 20 页

识别模式

  • standard：适合可复制文字 PDF、Excel、Word 和其他正文清晰文件，通常速度更快。
  • high_accuracy：适合扫描 PDF、独立图片和 Word 内嵌截图。Excel、Word 正文和表格仍按标准方式解析，处理时间通常更长。
同一个 Idempotency-Key 用于同一次业务请求的安全重试。不同文件、不同业务或不同识别模式必须使用新键。

4. 异步 JSON 文本抽取

POST/api/v1/extract/async

适用于客户系统已经完成邮件正文、OCR 或附件表格解析的场景。该接口接收预解析文本，不接收 Base64 原始文件，也不使用 high_accuracy。

JSON 字段必填说明
mail_subject否邮件主题，最长 255 字符
mail_body条件必填与 attachments 至少一项包含有效内容
attachments条件必填预解析附件数组，最多 10 项
callback_url否公网 HTTPS 回调地址
 
{
  "mail_subject": "Booking Confirmation",
  "mail_body": "POL: YANTIAN\nPOD: MELBOURNE\nBOOKING NO: BK123456",
  "attachments": []
}

5. 同步 JSON 抽取

POST/api/v1/extract/sync

请求会等待抽取完成后直接返回结果，只建议用于小规模文本联调。请求字段与异步 JSON 基本一致，但不包含 callback_url。

同步成功时业务结果从 data 读取；如返回超时且附带 task_id，应先查询该任务，不要立即重复创建。

6. 任务查询与结果读取

GET/api/v1/tasks/{task_id}

状态含义客户端处理
PENDING已接收，等待处理约 3 秒后再查
PROCESSING正在解析或抽取继续等待，不要高频请求
SUCCESS处理成功异步任务从 result_json 读取结果
FAILED处理失败读取 error_message 并根据原因处理

同步接口从 data 读取结果，异步任务查询从 result_json 读取结果，两条路径不能混用。

7. Webhook 回调与验签

配置 callback_url 后，任务成功或失败时系统会主动通知客户服务。正式环境只接受可从公网解析和访问的 HTTPS 地址；localhost、环回地址和内网 IP 会被拒绝。

X-Timestamp: 1788391200000
X-Signature-SHA256: <64 位十六进制签名>

签名原文为 timestamp + "." + 原始 HTTP 请求体字节，算法为 HMAC-SHA256。必须保存原始 body 后再解析 JSON，不能将 JSON 重新序列化后验签。

  • 建议拒绝时间偏差超过 5 分钟的通知。
  • 同一 task_id 重复到达时返回 2xx，但业务动作只执行一次。
  • Webhook Secret 只保存在客户回调服务端，不能当作 API Key 使用。

8. 输出字段规范

成功结果包含 57 个顶层字段，ContainerInfo 为箱明细数组。字段名区分大小写，客户端应允许空字符串、空数组并忽略未来可能增加的未知字段，不应依赖 JSON 字段顺序。

分类字段
收发通ShipperName, ShipperAddr, ShipperTel, ShipperEmail, ShipperFax, ConsigneeName, ConsigneeAddr, ConsigneeTel, ConsigneeEmail, ConsigneeFax, NotifyName, NotifyAddr, NotifyTel, NotifyEmail, NotifyFax
港口与地点POR, PORName, POL, POLName, POD, PODName, TransPort, DeliveryCode, DeliveryName
船期与航次ETD, ETA, Vessel, Voyage, CutOffDate, SICutOff
箱货与总计ContainerInfo, TotalContainerQty, GoodsName, GoodsNameCN, Marks, HSCode, Packages, PackagesUnit, GrossWeight, GrossWeightUnit, NetWeight, NetWeightUnit, Volume, VolumeUnit
条款与单证Incoterms, Movement, PackingMode, GoodsType, FreightTerm, Carrier, IsTrucking, IsCustomsDeclare, ReleaseBLType, BookingNo, BLNo, ContractNo, Remark

ContainerInfo 每个对象包含 13 个字段：ContainerNo, SealNo, ContSize, ContType, KGS, KGSunit, PCS, Package, CBM, CBMunit, HSCode, GoodsName, GoodsNameCN。

没有明确箱明细时必须返回 ContainerInfo=[]，不能返回只包含空字段的箱对象。如果除默认 GoodsType="S" 外其他字段均为空，任务应标记为 FAILED，并提示“模型返回空提取结果”。

9. 状态码、重试与排障

HTTP / 业务码场景处理
200请求成功或任务已接收异步返回 200 不代表任务已完成，继续查询状态
401API Key 缺失、无效或停用检查鉴权请求头，不要原样重试
402 / 40201可用余额不足联系项目方处理后重试
409 / 40902同一幂等键用于不同识别模式为新请求生成新键
413 / 41301-41303单文件、文件数或总量超限压缩、转换或拆分文件
415 / 41501文件扩展名不支持转换为支持的格式
422 / 42201callback_url 不安全使用可公网访问的 HTTPS 地址
429待处理任务达到上限遵循 Retry-After 延后重试
503 / 50301任务已保存但队列暂不可用保留 task_id 和原幂等键，稍后查询或安全重试
504 / 50401同步等待超时先查询返回的 task_id，不要重复创建

空结果排查顺序：确认文件可打开且包含业务内容 → 查看 status 和 error_message → 扫描 PDF 或图片改用 high_accuracy → 使用新幂等键重试。

10. 完整文件调用示例（Windows PowerShell）

以下流程完成：健康检查 → 安全输入 API Key → 上传文件 → 轮询任务 → 保存抽取结果。

10.1 设置参数

$baseUrl = "https://115.29.213.72:30010"
$filePath = "C:\CargoPlusTest\sample.pdf"
$recognitionMode = "standard"  # 扫描件可改为 high_accuracy

if (-not (Test-Path -LiteralPath $filePath)) {
    throw "找不到测试文件：$filePath"
}

$secureKey = Read-Host "请输入测试 API Key（输入内容不会显示）" -AsSecureString
$apiKey = [System.Net.NetworkCredential]::new("", $secureKey).Password
$headers = @{ "Authorization" = "Bearer $apiKey" }

10.2 健康检查

$health = Invoke-RestMethod -Method Get -Uri "$baseUrl/health/ready"
$health | ConvertTo-Json -Depth 10
if ($health.status -ne "ready") { throw "服务尚未就绪" }

10.3 上传文件

$idempotencyKey = [guid]::NewGuid().ToString()
$curlArguments = @(
    "-sS", "--ssl-revoke-best-effort", "-X", "POST",
    "$baseUrl/api/v1/extract/async/upload",
    "-H", "Authorization: Bearer $apiKey",
    "-H", "Idempotency-Key: $idempotencyKey",
    "-F", "files=@$filePath",
    "-F", "mail_subject=客户API文件抽取测试",
    "-F", "recognition_mode=$recognitionMode"
)
$submitRaw = & curl.exe @curlArguments
if ($LASTEXITCODE -ne 0) { throw "文件上传失败，curl退出码：$LASTEXITCODE" }
$submitResult = $submitRaw | ConvertFrom-Json
if (-not $submitResult.task_id) { throw "服务器没有返回 task_id：$submitRaw" }
$taskId = $submitResult.task_id
Write-Host "任务编号：" $taskId
Write-Host "初始状态：" $submitResult.status
Windows 自带的 curl.exe 可能无法联机检查内部 CA 证书的吊销状态，因此示例使用 --ssl-revoke-best-effort。该选项仍会校验证书链和服务器 IP，不等同于 -k 或关闭 TLS 验证。如上传命令报错，请立即停止，不要继续执行 task_id 查询步骤。

10.4 轮询直到完成

$maximumWaitSeconds = 900
$stopwatch = [System.Diagnostics.Stopwatch]::StartNew()
do {
    $task = Invoke-RestMethod -Method Get `
        -Uri "$baseUrl/api/v1/tasks/$taskId" -Headers $headers
    Write-Host "当前状态：" $task.status
    if ($task.status -in @("PENDING", "PROCESSING")) { Start-Sleep -Seconds 3 }
    if ($stopwatch.Elapsed.TotalSeconds -ge $maximumWaitSeconds) {
        throw "等待超时，请保留任务编号：$taskId"
    }
} while ($task.status -in @("PENDING", "PROCESSING"))
$stopwatch.Stop()

10.5 读取并保存结果

if ($task.status -eq "SUCCESS") {
    $resultText = $task.result_json | ConvertTo-Json -Depth 30
    $outputPath = Join-Path ([Environment]::GetFolderPath("Desktop")) `
        "CargoPlus-$taskId-result.json"
    $resultText | Set-Content -LiteralPath $outputPath -Encoding UTF8
    Write-Output $resultText
    Write-Host "结果已保存到：$outputPath"
} elseif ($task.status -eq "FAILED") {
    Write-Host "识别失败，任务编号：" $task.id
    Write-Host "失败原因：" $task.error_message
} else {
    Write-Host "未知任务状态：" $task.status
}
PENDING 只表示任务已接收，不代表抽取完成。标准模式下 vision_pages_processed=0 可能是正常情况：系统可以先读取 PDF 文字，再进行业务字段抽取，不一定需要视觉识别。
